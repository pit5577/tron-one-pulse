# УТ-1: перевод TRX через наш узел (16.11)

Решение Ивана 16.11: узел пропускает перевод TRX, полосу дает Банк, 0,32 TRX списываются со счета после перевода в сети; отказ сети - не списываем.

## Сервер (server.diff, база wt-mail aff23da, server_BASE_MD5)
- POST /charge `{legs:"bandwidth", transfer:"trx"}` - только с x-node-energy-token. Иное сочетание - 400 bad_legs.
- Потребность по полосе отправителя (USDT не читаем). Пул 351 покрывает - ноги нет, денег нет.
- Зарядка `state.asset="trx"`: живой проверки USDT нет; перевод клиента ищется среди переводов TRX (TransferContract SUCCESS).
- Проводка: «зарядка … · полоса для перевода TRX». Ответ повторяет `transfer:"trx"`.
- Тесты: test/ut1_trx_transfer.test.ts (8). Весь набор: 1545, падений 0. Новых ошибок tsc нет (43 до и после).

## Узел (node.diff, база снимок node-253c450a-vres-cloud, node_BASE_MD5)
- Флаг NODE_TRX=on (+ NODE_TRX_SWITCH файл «off»). Нужен NODE_ENERGY_TOKEN. Выкл - прежний отказ only_usdt.
- Перевод TRX с адреса с подменой ресурсов: своя полоса - сразу; нет - нога Банка, ждем полосу в сети, отправляем.
- Получатель не активирован - отказ до зарядки (сеть сожгла бы 1 TRX).
- Сеть прямо отклонила перевод - charge-not-used сразу (П3). Неясный ответ 5xx - не трогаем.
- Сервер не повторил transfer:"trx" (старый сервер) - перевод не отправлен, удержание снято, ALARM.
- Тесты: test/trx.test.ts (11). Весь набор: 126, падений 0.

## Ворота (замок КП-1)
- transfer_gate.sh + test_transfer_gate.sh (6 проверок, зеленые). deploy_one_G6.diff - вызов в воротах deploy_one.
- Разовая подготовка песочницы: ~/nile-gate/key, via, to (см. шапку скрипта); узел Nile с NODE_TRX=on.

## Порядок выкладки
1. Сервер (поездом). 2. Узел Nile с NODE_TRX=on, transfer_gate зеленый. 3. Узел боя NODE_TRX=on. 4. П1: Иван шлет остаток TRX на Банк через наш узел.
Откат узла: файл NODE_TRX_SWITCH = off, без перезапуска.
